# Inversion

Переверни один предмет: назови худшее решение, запиши, почему оно плохое, и собери хорошее решение из этих причин. Слот промпта — одна проблема или одно решение. Несколько несвязанных предметов слотом не являются.

Результат — худшая картина, причины, по которым она плоха, и хорошее решение, которое закрывает каждую причину.

## Куда писать

`.rdd/inversion/<предмет>.md`

Один файл на один предмет. Имя файла — kebab-case предмета: нижний регистр, слова через дефис, латиница (`Запуск оплаты` → `zapusk-oplaty.md`). Каталог создавай вместе с первым файлом. Повторный запуск для того же предмета обновляет этот файл. Если в файле стоит `> пробел:`, продолжи с этого места. Сначала прочитай каталог: тот же предмет под другим написанием имени — обновляй его, второй файл не создавай. В файле уже другой предмет — задай один вопрос и остановись. Каталог `.rdd/` коммитится вместе с репозиторием.

Язык файла — язык, на котором назван предмет. Заголовки блоков оставь как в формате.

## Ход

1. Возьми предмет из сообщения пользователя: проблему или решение, которое пока видно только с удачной стороны. Предмета нет — задай один вопрос, что переворачиваем, и остановись до ответа. Названо несколько несвязанных предметов — задай один вопрос, какой берём, и остановись. Готово, когда есть один предмет одним предложением и имя файла в kebab-case.
2. Прочитай репозиторий и `.rdd/` на опору предмета: условия, уже названные сбои, уже записанные решения. Готово, когда каждый заимствованный факт указан путём к файлу либо в репозитории опоры не нашлось.
3. Назови худшее решение в этой ситуации. Это картина для обхода, не прогноз. Противоположное удачной картине помогает её назвать. Предмет — проект: картина фиксирована так — через шесть месяцев проект провалился. Из предмета не собрать даже худшее решение — поставь `> пробел:`, задай один вопрос, в какой ситуации его принимают, и остановись. Готово, когда худшее решение записано одним конкретным решением или итогом, а для проекта в нём есть провал через шесть месяцев.
4. Запиши, почему это плохо. Собери причины вопросами: почему это плохо; как это ломается; что сделало бы решение плохим. Для проекта добавь: что пошло не так; какие ошибки сделали; почему проект провалился. Причина из сообщения или репозитория идёт с опорой. Причина, которую ты выводишь из уже известного предмета, остаётся возможной: помечай её `вариант`. Причина, которой нужен факт, которого нет в источниках, в список не входит. После этого причин меньше двух — поставь `> пробел:`, запиши файл без хорошего решения, задай один вопрос, чем ещё это плохо, и остановись. Готово, когда записаны хотя бы две причины и каждая говорит, чем худшее плохо, а не повторяет его название.
5. Собери хорошее решение, глядя на причины. На каждую причину — строка, как это решение её закрывает. Причина без такой строки — решение ещё не собрано. Части, которых не было в источниках, помечай `вариант`. Готово, когда хорошее решение записано и у каждой причины есть строка, как оно её закрывает.
6. Запиши файл в формате ниже, включая остановку на пробеле: разделы после пробела не заполняй. Готово, когда файл лежит по пути из первого раздела, а ответ называет этот путь, хорошее решение одной фразой и остановился ли ход на пробеле.

## Формат файла

Один markdown-файл:

- заголовок `#` с предметом;
- строка `Предмет:` — проблема или решение одним предложением;
- «Худшее» — худшее решение; для проекта — провал через шесть месяцев;
- «Почему это плохо» — причины; у причины из источника строка `Опора`; у возможной причины пометка `вариант`;
- «Хорошее решение» — решение и на каждую причину строка, как оно её закрывает; у новой части пометка `вариант`.

Дырка в знаниях — цитата `> пробел:`.

## Держать

- Худшее — картина, от которой собирают хорошее решение.
- Хорошее решение собрано из причин. На каждую причину видно, как оно её закрывает.
- Причина, которой нужен отсутствующий факт, в список не попадает.
- Для проекта худшая картина — провал через шесть месяцев.
- В одном файле один предмет.
- В одном запуске один вопрос.
