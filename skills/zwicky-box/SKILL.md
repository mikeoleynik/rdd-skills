# Zwicky box

Собери ящик Цвикки одной задачи: независимые параметры, значения и сочетания, которые читаются как целые решения. Слот промпта — одна задача. Исходный пример, если он назван, разбирается на части и занимает одно сочетание. Несколько несвязанных задач слотом не являются.

Результат — параметры, значения, число сочетаний и сырые сочетания. Среди сырых есть странное. Рабочее решение из них собирает тот, кто читает файл.

## Куда писать

`.rdd/zwicky-box/<задача>.md`

Один файл на одну задачу. Имя файла — kebab-case задачи: нижний регистр, слова через дефис, латиница (`Срок поставки заказа` → `srok-postavki-zakaza.md`). Каталог создавай вместе с первым файлом. Повторный запуск для той же задачи обновляет этот файл. Если в файле стоит `> пробел:`, продолжи с этого места. Сначала прочитай каталог: та же задача под другим написанием имени — обновляй его, второй файл не создавай. В файле уже другая задача — задай один вопрос и остановись. Каталог `.rdd/` коммитится вместе с репозиторием.

Язык файла — язык, на котором названа задача. Заголовки блоков оставь как в формате.

## Ход

1. Возьми задачу из сообщения пользователя. Её нет — задай один вопрос и остановись до ответа. В сообщении только готовое решение — слот это задача, которую решение закрывает; задай один вопрос, какую задачу разбираем, и остановись. Названо несколько несвязанных задач — задай один вопрос, какую берём, и остановись. Готово, когда есть одна задача и имя файла в kebab-case.
2. Прочитай репозиторий и `.rdd/` на опору задачи: части, свойства, уже записанные ящики. Готово, когда каждый заимствованный факт указан путём к файлу либо в репозитории опоры не нашлось.
3. Назови параметры. Параметр — ось задачи: свойство, часть, функция или элемент. Ось релевантна задаче. Оси логически независимы: значение одной не выводится из значения другой, иначе их нельзя сочетать. Бери оси из задачи, из опоры и из исходного примера — перечисли его части и подними их до осей. Ось, которой в источниках нет, помечай `вариант`. В источниках меньше двух осей — сначала назови ещё одну ось, которая дробит задачу, и пометь её `вариант`. Вторую ось так и не назвать — задай один вопрос, какое свойство ещё меняется, и остановись. Две оси зависят друг от друга, и развести их нечем — задай один вопрос, как их разделить, и остановись. Готово, когда осей две или больше, ни одна пара не выводится одна из другой, а ось вне источников помечена `вариант`.
4. По каждой оси выпиши значения. Значение из сообщения, файла или исходного примера идёт с опорой. Сверх источников добавь ещё значения этой оси, в том числе те, что кажутся невозможными, и помечай их `вариант`. Ось, на которой после этого одно значение, — поставь на ней `> пробел:`, запиши файл без ящика и сочетаний, задай один вопрос, какое ещё значение у неё бывает, и остановись. Готово, когда у каждой оси два или больше значений, у каждого есть опора или пометка `вариант`, и на оси есть хотя бы одно значение с пометкой `вариант`.
5. Собери ящик и сочетания. Сначала допиши на оси значения исходного примера, которых ещё нет, с опорой. Сочетание — ровно одно значение с каждой оси и одна фраза, какое целое решение из этого получается. Число сочетаний — произведение чисел значений. Способ бери из сообщения. `все` — список длиной в произведение. `случайно` — набор названного числа; числа нет — поставь в сочетаниях `> пробел:`, запиши ящик, задай один вопрос, сколько сочетаний писать, и остановись. `фокус` — только сочетания по названным осям или значениям; фокус не назван — поставь `> пробел:`, запиши ящик, задай один вопрос, на чём фокус, и остановись. Способа нет — `обход`: каждое значение входит хотя бы в одно сочетание, и среди сочетаний есть странное. Странное — сочетание, которое на первый взгляд не сходится; фраза целого решения у него есть, из списка его не убирай. Внутри `все`, `случайно` и `фокус` странное сочетание, попавшее в набор, тоже остаётся. Исходный пример посади на его сочетание. Готово, когда произведение посчитано, способ назван, у каждого записанного сочетания есть значение с каждой оси и фраза целого решения, правило способа выполнено, и исходный пример либо сидит на сочетании, либо его не было.
6. Запиши файл в формате ниже, включая остановку на пробеле: разделы после пробела не заполняй. Готово, когда файл лежит по пути из первого раздела, а ответ называет этот путь, число сочетаний, способ и остановился ли ход на пробеле.

## Формат файла

Один markdown-файл:

- заголовок `#` с задачей;
- строка `Исходный пример:` — пример, с которого снимали оси, или `нет`;
- «Параметры» — ось, затем её значения; у значения опора или пометка `вариант`; у оси без источника пометка `вариант`;
- «Ящик» — таблица «параметр / значения», строка с произведением и строка `Способ:` (`все`, `случайно`, `фокус` или `обход`);
- «Сочетания» — у каждого значения по осям и фраза целого решения; странное помечено `странное`.

Дырка в знаниях — цитата `> пробел:`.

## Держать

- Параметр дробит задачу на независимую ось. Значение — состояние этой оси. Сочетание берёт по одному состоянию с каждой оси и читается как одно целое решение.
- Значение, которое кажется невозможным, на оси остаётся.
- `вариант` называет предложенную ось или предложенное значение. Факт о задаче стоит там, где есть опора.
- Странное сочетание остаётся среди сырых сочетаний.
- Исходный пример занимает одно сочетание. Остальное поле остаётся в ящике.
- В одном запуске один вопрос.
