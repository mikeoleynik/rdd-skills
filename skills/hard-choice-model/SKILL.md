# Модель трудного выбора

Определи, какое это решение, по влиянию исхода и по тому, насколько легко сравнить варианты, и запиши подход этого типа. Слот промпта — одно решение. Решение без вариантов и несколько несвязанных решений слотом не являются.

Две оси. Влияние: насколько значим исход. Сравнимость: насколько легко сравнить варианты. Из осей выходит один из четырёх типов. Чем значимее исход, тем тщательнее подход.

## Куда писать

`.rdd/hard-choice-model/<решение>.md`

Один файл на одно решение. Имя файла — kebab-case решения: нижний регистр, слова через дефис, латиница (`Выбор офиса` → `vybor-ofisa.md`). Каталог создавай вместе с первым файлом. Повторный запуск для того же решения обновляет этот файл. Если в файле стоит `> пробел:`, продолжи с этого места. Сначала прочитай каталог: то же решение под другим написанием имени — обновляй его, второй файл не создавай. В файле уже другое решение — задай один вопрос и остановись. Каталог `.rdd/` коммитится вместе с репозиторием.

Язык файла — язык, на котором названо решение. Имена типов оставь как в формате.

## Ход

1. Запиши решение из сообщения пользователя. Его нет — задай один вопрос, какое решение разбираем, и остановись до ответа. Названо несколько несвязанных решений — задай один вопрос, какое берём, и остановись. Выпиши варианты, между которыми идёт выбор. Варианты — те, что назвал пользователь. Список из файла, на который он указал, берётся оттуда. Вариантов меньше двух — запиши решение и `> пробел:` на вариантах, задай один вопрос, какие варианты сравниваем, и остановись. Тип в этот запуск не назначай. Готово, когда решение сформулировано одним предложением, в списке два или больше вариантов и имя файла в kebab-case, либо ход остановился на одном вопросе.

2. Прочитай репозиторий и `.rdd/` на опору влияния исхода и сравнимости вариантов. Готово, когда каждый заимствованный факт указан путём к файлу либо в репозитории опоры не нашлось.

3. Ответь по источникам на два вопроса. Насколько значим исход: высокое влияние или низкое. Насколько легко сравнить варианты: легко или трудно. Легко — варианты сопоставимы. Трудно — варианты разной природы, их не на что положить рядом. Ответ по оси берётся из сообщения или файла и идёт с опорой. Опоры на ось нет — на этой оси `> пробел:`, тип не назначай, запиши файл до этого места, задай один вопрос по первой пустой оси и остановись. Подход в этот запуск не пиши. Готово, когда у обеих осей есть ответ с опорой, либо ход остановился на одном вопросе.

4. Назначь тип и запиши его подход. Низкое влияние и легко сравнить — `No-brainer`: решить быстро, доводка здесь тратит время. Низкое влияние и трудно сравнить — `Apples and Oranges`: опереться на то, что важно сейчас, решить по текущим приоритетам. Высокое влияние и легко сравнить — `Big choice`: собрать достаточно сведений и уверенность через тщательное сравнение. Высокое влияние и трудно сравнить — `Hard choice`: принять, что одного правильного ответа нет; оценить разные факторы, для этого подходит матрица решений; малый опыт, когда он возможен, снижает риск. Готово, когда у решения ровно один тип и подход этого типа.

5. Допиши вход подхода, если тип его требует. `Apples and Oranges`: строка `Сейчас важно` — приоритет из источников. Приоритета в источниках нет — `> пробел:`. `Big choice`: строка `Что сравниваем` — сведения, которые источники уже дают для сравнения. Сведений нет — `> пробел:`. `Hard choice`: строка `Факторы` — факторы, которые уже названы; не названы — `> пробел:`. Строка `Малый опыт` — опыт, который источники уже описывают; не описывают — `> пробел:`. Матрицу факторов в этот файл не собирай. `No-brainer` дополнительных строк не требует. Хотя бы одна такая строка с пробелом — в ответе один вопрос по первой из них. Готово, когда обязательные строки типа либо с опорой, либо как пробел.

6. Запиши файл в формате ниже. Готово, когда файл лежит по пути из первого раздела, а ответ называет этот путь, тип и осталась ли строка подхода с пробелом.

## Формат файла

Один markdown-файл:

- заголовок `#` с решением;
- строка `Решение:` — одно предложение;
- «Варианты» — список вариантов;
- строка `Влияние:` — высокое или низкое, опора;
- строка `Сравнимость:` — легко или трудно, опора;
- строка `Тип:` — одно из имён `No-brainer`, `Apples and Oranges`, `Big choice`, `Hard choice`; осей ещё нет — `> пробел:`;
- строка `Подход:` — подход этого типа;
- строки входа подхода — только те, которые шаг 5 требует для этого типа; у каждой опора или `> пробел:`.

Дырка в знаниях — цитата `> пробел:`.

## Держать

- Тип назначается по двум осям: значимость исхода и лёгкость сравнения вариантов.
- Чем значимее исход, тем тщательнее подход. Низкое влияние получает быстрый ход.
- Подход `Hard choice` называет матрицу решений и малый опыт. Сама матрица в этом файле не строится.
- В одном файле одно решение.
