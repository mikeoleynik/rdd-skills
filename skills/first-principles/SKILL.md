# Первые принципы

Дойди от одной проблемы до первых принципов и собери решение заново из этих принципов. Первый принцип — истина, которую дальше не разложить. Слот промпта — одна проблема. Готовое решение и несколько несвязанных проблем слотом не являются.

Результат — принципы с опорой и решение, каждая часть которого взята из этих принципов.

## Куда писать

`.rdd/first-principles/<проблема>.md`

Один файл на одну проблему. Имя файла — kebab-case проблемы: нижний регистр, слова через дефис, латиница (`Дорогая доставка` → `dorogaya-dostavka.md`). Каталог создавай вместе с первым файлом. Повторный запуск для той же проблемы обновляет этот файл. Если в файле стоит `> пробел:`, продолжи с этого места. Сначала прочитай каталог: та же проблема под другим написанием имени — обновляй его, второй файл не создавай. В файле уже другая проблема — задай один вопрос и остановись. Каталог `.rdd/` коммитится вместе с репозиторием.

Язык файла — язык, на котором названа проблема. Заголовки блоков оставь как в формате.

## Ход

1. Возьми проблему из сообщения пользователя. Её нет — задай один вопрос, какую проблему разбираем, и остановись до ответа. В сообщении только готовое решение — слот это проблема, которую решение закрывает; задай один вопрос, какую проблему разбираем, и остановись. Названо несколько несвязанных проблем — задай один вопрос, какую берём, и остановись. Готово, когда есть одна проблема одним предложением и имя файла в kebab-case.
2. Прочитай репозиторий и `.rdd/` на опору проблемы: утверждения, ограничения, уже записанные разборы. Готово, когда каждый заимствованный факт указан путём к файлу либо в репозитории опоры не нашлось.
3. Разложи проблему на утверждения и копай, пока каждое оставшееся не станет первым принципом: дальше его не из чего сложить. Копай повторным «почему». Пять вопросов — не граница: граница там, где утверждение больше не делится. Опора принципа — цитата пользователя или путь к файлу. Утверждение ещё делится, а ответа в источниках нет — это ещё не принцип. Поставь `> пробел:`, запиши уже опертые принципы, задай один вопрос и остановись. Раздел «Решение» на этом запуске не заполняй. Вопрос один, по типу затыка. Смысл слова неясен — «Что вы имеете в виду под …?». Утверждение держится на допущении — «Что можно принять вместо этого?». Названа причина без опоры — «Почему это правда?». Нужен эффект, которого в источниках нет — «Какой эффект это даст?». Видна только одна сторона, а основание не достигнуто — «Какая есть альтернатива?». Упирается сама постановка вопроса — «В чём был смысл этого вопроса?». Готово, когда каждый записанный принцип дальше не делится и у него есть опора, либо ход остановился на одном вопросе.
4. Собери решение из принципов, которые уже записаны с опорой. Пропусти шаг, если ход остановился на пробеле. Каждая часть решения называет принцип, из которого она взята. Часть, которую нельзя указать на записанный принцип, в решение не клади. Готово, когда решение записано и у каждой его части назван принцип-источник.
5. Запиши файл в формате ниже, включая остановку на пробеле: раздел «Решение» после пробела не заполняй. Готово, когда файл лежит по пути из первого раздела, а ответ называет этот путь, решение одной фразой или что его ещё нет, и остановился ли ход на пробеле.

## Формат файла

Один markdown-файл:

- заголовок `#` с проблемой;
- строка `Проблема:` — одно предложение;
- «Принципы» — у каждого утверждение, строка `Дальше не делится` и строка `Опора`;
- «Решение» — части решения, у каждой строка `Из принципа`.

Дырка в знаниях — цитата `> пробел:`.

## Держать

- Принцип — утверждение, которое больше не из чего сложить. Опора показывает, откуда оно известно.
- Граница копания — неразложимая истина. Число вопросов «почему» под эту границу подстраивается.
- Решение собирается из записанных принципов: у каждой части назван принцип-источник.
- На одном запуске звучит один вопрос.
- В одном файле одна проблема.
