# Метод исключения

Убери элемент существующей модели и посмотри, каким другим способом получается его результат. Слот промпта — один предмет: продукт, система, процесс, сценарий, решение или идея, у которых есть текущее устройство. Пустой предмет и несколько несвязанных предметов слотом не являются.

Исключение элемента оставляет шанс найти другой способ получить его результат. Провокация — вопрос «что, если этого элемента не будет?». Идея появляется после последствий этой провокации.

## Куда писать

`.rdd/elimination-method/<предмет>.md`

Один файл на один предмет. Имя файла — kebab-case предмета: нижний регистр, слова через дефис, латиница (`Текущая оплата` → `tekushchaya-oplata.md`). Каталог создавай вместе с первым файлом. Повторный запуск для того же предмета обновляет этот файл. Если в файле стоит `> пробел:`, продолжи с этого места. Сначала прочитай каталог: тот же предмет под другим написанием имени — обновляй его, второй файл не создавай. В файле уже другой предмет — задай один вопрос и остановись. Каталог `.rdd/` коммитится вместе с репозиторием.

Язык файла — язык, на котором назван предмет. Заголовки блоков оставь как в формате.

## Ход

1. Возьми предмет из сообщения пользователя. Его нет — задай один вопрос, что разбираем, и остановись до ответа. Названо несколько несвязанных предметов — задай один вопрос, какой берём, и остановись. Запиши, как предмет устроен сейчас. Устройство берётся из сообщения или из файла, на который пользователь указал. Устройства там нет — запиши предмет и `> пробел:` на устройстве, задай один вопрос, как это устроено сейчас, и остановись. Элементы в этот запуск не выделяй. Цель пользователя названа — запиши её. Не названа — в цели строка: найти другой способ получить результат без привычного элемента. Объём пользователь сузил — запиши, какие части разбираем. Не сузил — объём равен элементам, которые шаг 3 найдёт в устройстве. Статус — слово пользователя: Draft, Explored или Reviewed. Слова нет — Draft. Готово, когда есть один предмет, его устройство с опорой и имя файла в kebab-case, либо ход остановился на одном вопросе.

2. Прочитай репозиторий и `.rdd/` на опору устройства: части, роли, правила, ресурсы, порядок действий, то, что описание подаёт как обязательное. Готово, когда каждый заимствованный факт указан путём к файлу либо в репозитории опоры не нашлось.

3. Выдели элементы, которые описание уже содержит. Элемент — функция, компонент, шаг, роль, правило, ресурс, ограничение, привычный способ взаимодействия или допущение о том, как это работает. В список входят и те элементы, которые описание подаёт как обязательные. У элемента две строки: зачем он сейчас и на чём это видно. Зачем не сказано — на назначении `> пробел:`. Элемента, которого нет в устройстве, в список не добавляй. Объём пользователь не сузил — запиши его списком этих элементов. Список пуст — `> пробел:`, задай один вопрос, из каких элементов состоит текущее устройство, и остановись. Хотя бы у одного элемента назначение с пробелом — запиши список, задай один вопрос по первому такому элементу и остановись. Провокации в этот запуск не пиши. Готово, когда каждый элемент взят из устройства и у него есть назначение с опорой, объём записан, либо ход остановился на одном вопросе.

4. Для каждого элемента сформулируй провокацию: что, если этого элемента не будет. Вопрос убирает элемент целиком. Готово, когда у каждого элемента есть вопрос об его отсутствии.

5. Для каждой провокации запиши пять строк. Каждая строка берётся из устройства и уже записанных фактов и идёт с опорой. Опоры нет — на строке `> пробел:`, следствие из догадки не пиши.

   - Что перестаёт работать.
   - Что остаётся.
   - Какая возможность появляется.
   - Какое допущение больше не обязательно.
   - Каким другим способом получается прежний результат.

   Готово, когда у каждой провокации пять строк и у каждой строки опора или пробел.

6. Сформулируй идею по провокации, у которой все пять строк с опорой. Идея называет другой способ получить результат элемента: другой механизм, перенос функции в другое место, распределение по нескольким частям, отказ от функции или смена нужды в ней. Идея собирается из строк «возможность» и «другой способ». Провокация с пробелом идею в этот запуск не получает. Ценность идеи берётся из источников; в источниках её нет — на ценности `> пробел:`. Ни одной полной провокации нет — идеи не пиши, запиши файл до последствий, задай один вопрос по первой строке с пробелом и остановись. Готово, когда у каждой полной провокации есть идея другого способа, а провокация с пробелом остаётся без идеи.

7. Запиши наблюдения по уже записанным последствиям. Наблюдение — скрытая зависимость, ограничение, без которого модель живёт, функция, которая нужна только из-за другой функции, другой способ получить результат, возможность, которую открыло исключение, неожиданная связь частей. У наблюдения опора. Толкование пиши отдельно и привязывай к наблюдению, из которого оно следует. Связи в последствиях нет — в наблюдениях строка `нет`. Готово, когда каждое наблюдение опирается на записанное последствие, а толкование стоит отдельно от него.

8. Для каждой идеи запиши возможность, ограничение и что выяснить дальше. Возможность и ограничение берутся из источников или из уже записанных последствий. В источниках их нет — на этой строке `> пробел:`. Идея остаётся в списке при любом ограничении. Готово, когда у каждой идеи три строки, с опорой или с пробелом.

9. Запиши файл в формате ниже. Вопросы собери из пробелов: что неизвестно, почему это мешает идее или последствию, какое сведение сдвинет дело — последнее только если источник уже назвал, где его взять. Есть провокация без идеи — в ответе один вопрос по первой строке последствий с пробелом. Все идеи записаны, и осталась строка возможности с пробелом — один вопрос по первой такой идее. Готово, когда файл лежит по пути из первого раздела, а ответ называет этот путь, сколько идей записано и остались ли провокации без идеи.

## Формат файла

Один markdown-файл:

- заголовок `#` с предметом;
- «Контекст» — предмет, как устроено сейчас, цель, объём, статус; у устройства опора;
- «Элементы» — элемент, зачем он сейчас, опора; назначение неизвестно — `> пробел:`;
- «Провокации» — элемент и вопрос, что будет, если его не будет;
- «Последствия» — по провокации пять строк: что ломается, что остаётся, какая возможность, какое допущение больше не обязательно, какой другой способ; у строки опора или `> пробел:`;
- «Идеи» — идея, как работает, какой элемент закрывает, ценность; провокация с пробелом в этот блок не входит;
- «Наблюдения» — наблюдение с опорой; толкование отдельной строкой при наблюдении;
- «Возможности» — идея, возможность, ограничение, что выяснить;
- «Вопросы» — пробелы: что неизвестно и почему это мешает.

Дырка в знаниях — цитата `> пробел:`. Пустой блок — строка `нет`.

## Держать

- В списке элементов есть и те, что устройство подаёт как обязательные.
- Провокация убирает элемент целиком. Последствия разбирают эту провокацию до того, как появляется идея.
- В последствиях рядом стоят поломка, сохранившееся, новая возможность, поколебленное допущение и другой способ получить результат.
- Идея получает результат элемента другим способом: другой механизм, перенос, распределение, отказ от функции или другая нужда.
- Наблюдение и толкование стоят разными строками.
- Идея остаётся в списке, когда ограничение велико или убрать элемент в действительности нельзя. В идею попадает то изменение, которое уже следует из записанных последствий.
- В одном файле один предмет.
