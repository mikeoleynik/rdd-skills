# Матрица решений

Собери таблицу вариантов и факторов, посчитай балл каждого варианта и назови вариант с наибольшей суммой. Слот промпта — одно решение, у которого несколько вариантов. Одно решение без вариантов и несколько несвязанных решений слотом не являются.

Балл варианта — сумма произведений: балл на факторе умножается на вес фактора. Больший балл на шкале означает лучшее значение фактора.

## Куда писать

`.rdd/decision-matrix/<решение>.md`

Один файл на одно решение. Имя файла — kebab-case решения: нижний регистр, слова через дефис, латиница (`Выбор поставщика` → `vybor-postavshchika.md`). Каталог создавай вместе с первым файлом. Повторный запуск для того же решения обновляет этот файл. Если в файле стоит `> пробел:`, продолжи с этого места. Сначала прочитай каталог: то же решение под другим написанием имени — обновляй его, второй файл не создавай. В файле уже другое решение — задай один вопрос и остановись. Каталог `.rdd/` коммитится вместе с репозиторием.

Язык файла — язык, на котором названо решение. Заголовки блоков оставь как в формате.

## Ход

1. Запиши решение, которое нужно принять, из сообщения пользователя. Его нет — задай один вопрос, какое решение принимаем, и остановись до ответа. Названо несколько несвязанных решений — задай один вопрос, какое берём, и остановись. Готово, когда решение сформулировано одним предложением и имя файла в kebab-case.

2. Выпиши варианты, между которыми идёт выбор. Варианты — те, что назвал пользователь. Список вариантов в файле, на который он указал, берётся оттуда. Вариантов меньше двух — запиши решение и `> пробел:` на вариантах, задай один вопрос, какие варианты сравниваем, и остановись. Таблицу факторов в этот запуск не заполняй. Готово, когда в списке два или больше вариантов, либо ход остановился на одном вопросе.

3. Выпиши факторы, которые пользователь хочет учесть. Факторы из файла, на который он указал, берутся оттуда. Факторы, которых он не называл, в таблицу не добавляй. Факторов нет — запиши решение и варианты, поставь `> пробел:` на факторах, задай один вопрос, какие факторы учитываем, и остановись. Баллы в этот запуск не ставь. Готово, когда список факторов взят из названного пользователем, либо ход остановился на одном вопросе.

4. Прочитай репозиторий и `.rdd/` на опору баллов и весов по уже названным факторам. Готово, когда каждый заимствованный факт указан путём к файлу либо в репозитории опоры не нашлось.

5. Поставь каждому варианту балл на каждом факторе. Шкала — та, которую назвал пользователь. Шкалы нет — шкала от 1 до 5, где 1 худший исход, а 5 лучший. Больший балл — лучшее значение фактора, в том числе там, где «лучше» значит меньше цена или меньше затрата. Балл, который пользователь уже поставил, остаётся его баллом, опора — его сообщение. Балла нет — поставь его по факту из источников и запиши этот факт опорой. Факта для сравнения нет — в ячейке `> пробел:`, балл не ставь. Хотя бы одна ячейка с пробелом — запиши файл до этого места, задай один вопрос по первой такой ячейке и остановись. Веса и суммы в этот запуск не считай. Готово, когда у каждой ячейки есть балл и опора, шкала записана, либо ход остановился на одном вопросе.

6. Добавь вес каждому фактору. Вес берётся из сообщения или из файла, где важность фактора уже названа. Пользователь сказал, что факторы равнозначны — веса равны. Веса нет — поставь `> пробел:` на весах, запиши файл до этого места, задай один вопрос, какой у факторов вес, и остановись. Суммы в этот запуск не считай. Готово, когда у каждого фактора есть вес с опорой, либо ход остановился на одном вопросе.

7. Посчитай балл варианта: балл на факторе умножь на вес этого фактора, произведения сложи. Проверь, что сумма равна сумме произведений. Победитель — вариант с наибольшей суммой. Наибольшая сумма у нескольких вариантов — в победителях все они. Готово, когда у каждого варианта сумма сходится с произведениями и победитель назван по этой сумме.

8. Запиши файл в формате ниже. Готово, когда файл лежит по пути из первого раздела, а ответ называет этот путь, шкалу, победителя и осталась ли ячейка с пробелом.

## Формат файла

Один markdown-файл:

- заголовок `#` с решением;
- строка `Решение:` — одно предложение;
- строка `Шкала:` — диапазон и что означает больший балл;
- «Факторы» — фактор и его вес; у веса опора или `> пробел:`;
- «Баллы» — по варианту: на каждом факторе балл, опора балла, произведение балла на вес; затем сумма;
- «Победитель» — вариант с наибольшей суммой; при равной наибольшей сумме — все такие варианты; сумм ещё нет — `> пробел:`.

Дырка в знаниях — цитата `> пробел:`.

## Держать

- В таблице те варианты и те факторы, которые названы для этого решения.
- Больший балл означает лучшее значение фактора на записанной шкале.
- Сумма варианта равна сумме произведений балла на вес.
- Победитель — вариант с наибольшей суммой. Общая наибольшая сумма остаётся у всех, у кого она вышла.
- В одном файле одно решение.
